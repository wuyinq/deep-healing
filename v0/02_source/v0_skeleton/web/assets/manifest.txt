#      贴图**永不被放大**到比源照片还大（不伪造真实覆盖），且图案在每个构件上**至少平铺一次**。

#      瓦楞（≈0.84 m/道）。r1 把这种贴图 1:1 铺到 1.1 m 的门 / 0.14 m 的落水管上，构件只显示贴图的
#      百分之几 ⇒ 画面读作**纯色**（实测 `metal_corrugated` 的 repeat 只有 0.005185）。
#      逐表面的 basis 与 repeat 实测读数落 `v0/spikes/n4-art/readback/material-basis-<tag>.json`。
#      构件本就比扫描大的（墙 / 地面 / 屋顶）⇒ `basis = 扫描覆盖`，与 r1 读数**逐字相同**。
#   ③ 上游两字段冲突的一件（**不静默取舍**）：`leather_red_02` 的 `dimensions` = 600 cm 与

#      两个字段都记在 `readback/polyhaven-dimensions.json`。

# **真实尺度依据**（**三个不同的量，别混**；N4-r3 / R3-3 重写）：
#   ① **扫描覆盖** `scan_coverage_m` = Poly Haven 官方 API `https://api.polyhaven.com/info/<asset_id>`
#      的 `dimensions`（cm）/100 —— 「源照片拍多大一片」的上游读数，本表逐行抄录（写作「真实覆盖 N cm」）。
#      取值日期 2026-09-24，原始读数落 `readback/polyhaven-dimensions.json`。
#   ② **材质基准** `repeat_basis_m`（本表写作「**基准 N m**」）= 「这张贴图在**这个表面上**被映射到
#      多大一片」的**声明值**，与构件尺寸**无关**。`repeat = surface_size_m / repeat_basis_m`。
#      依据必须可核，逐表面带标签（`upstream` / `visually_corrected`）：
#        `upstream`           —— 取①。适用于**没有可数图案单元**的贴图（灰泥 / 沥青 / 拉毛混凝土 /
#                                草地 / 针织物 / 皮革粒面）—— 它们没有「一块砖」这样的尺度锚点。
#        `visually_corrected` —— **独立测量**「贴图内图案单元数 × 该单元的物理参照尺寸」，

#      约 5–20 倍。照抄①会让 `brick_wall_04` 的 13.9 m ÷ 贴图内 10 块砖 = **1.39 m 一块砖**（不可能）。
#      r2 的旧规则 `basis = min(扫描覆盖, min(构件尺寸))` 已被 architect **打回**：它使 `repeat ≥ 1` 与
#      `never_magnified` 成为**恒真式**（Raven N2-1），且 basis 由构件尺寸反推 ⇒ 与被验对象循环。
#      r3 口径下 `repeat < 1` **是允许且正确的物理结果**（1.1 m 的门铺 1.68 m 基准的板贴图 ⇒ 只显示
#      65% 的贴图）。代价（贴图放大倍数 = ①/②）逐表面给读数；`glass` 与 `fabric_cotton` 因此记 **GAP**。
#      逐表面 basis / repeat / 放大倍数落 `readback/material-basis-<tag>.json`。
#   ③ 上游两字段冲突的一件（**不静默取舍**）：`leather_red_02` 的 `dimensions` = 600 cm 与
#      `scale` = "30x30 cm" 相差 20×。本表采用 `scale`（30 cm）：皮革粒面是微观纹理，30 cm 量级与
